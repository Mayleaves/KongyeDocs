**千万不要给空叶文档换签名或卸载重装**：密码空间的密钥在空叶文档自己的 Android Keystore 里，一卸载密钥就没了，密码空间打不开。

## 1. 接口约定

### 1.1 权限

空叶文档声明，键盘和悬浮球申请：

```xml
<!-- 空叶文档 AndroidManifest.xml -->
<permission
    android:name="com.kongye.permission.VAULT"
    android:protectionLevel="signature"
    android:label="读取空叶文档密码空间" />

<!-- 空叶键盘、空叶悬浮球 AndroidManifest.xml -->
<uses-permission android:name="com.kongye.permission.VAULT" />
<queries>
    <package android:name="com.kongye.docs" />
</queries>
```

### 1.2 Provider

```xml
<!-- 空叶文档 -->
<provider
    android:name=".vault.VaultProvider"
    android:authorities="${applicationId}.vault"
    android:exported="true"
    android:permission="com.kongye.permission.VAULT" />
```

- 正式版地址：`content://com.kongye.docs.vault`
- 测试版（`.audit` / `.docktest` / `.upgradefixture`）自动用自己的地址，不和正式版冲突。键盘和悬浮球默认连正式版，调试时可在各自设置里改。
- 只用 `ContentResolver.call(uri, method, arg, extras)`，不用 `query()` 游标。所有返回都是 `Bundle`，**都带 `status` 字段**。

### 1.3 调用方白名单

Provider 内用 `callingPackage` 校验，只认这几个（签名权限之外再加一道）：

```
com.kongye.keyboard
com.kongye.keyboard.debug
com.kongye.floatball
```

不在白名单 → `status = "denied"`。

调试版（`.audit` 等可调试的测试包）额外允许自己调用自己，用来在测试包里跑通接口；正式版不可调试，不生效。

### 1.4 方法

| 方法 | 传入 extras | 返回 | 要解锁吗 |
|---|---|---|---|
| `status` | — | `version`(Int，当前 1)、`enabled`(Boolean)、`unlocked`(Boolean)、`unlockExpiresAt`(Long，毫秒) | 否 |
| `match` | `package`(String，目标 App 包名)、`domain`(String?，网页域名) | `entries`：`ArrayList<Bundle>`，每项 `id`、`name`、`account`(打码后，如 `138****5678`)、`matchedBy`(`"package"` / `"domain"`) | 否 |
| `search` | `query`(String) | 同 `match` 的 `entries`，`matchedBy = "search"` | 否 |
| `reveal` | `id`(String)、`package`(String) | 已解锁：`account`、`password`（明文）<br>未解锁：`status = "locked"` + `unlock`(PendingIntent) | **是** |
| `generate` | `length`(Int?，默认用空叶文档的设置) | `password` | 否 |
| `save` | `name`、`account`、`password`、`package`、`domain`(?) | `id`、`result`(`"created"` / `"updated"`)；账号 + 包名都相同时视为更新 | 否 |
| `bind` | `id`、`package`、`domain`(?) | — | 否 |

`status` 取值：`"ok"` / `"locked"` / `"disabled"`（设置开关没开）/ `"denied"`（不在白名单）/ `"not_found"` / `"error"`（附 `message`）。

约定：

- `match` / `search` 返回的账号是**打码后**的，真实账号和密码只从 `reveal` 拿。
- 密码明文只出现在 `reveal` 的返回里，调用方用完立即丢弃，**不写日志、不进剪贴板、不进词库、不落盘**。
- `match` 排序：按包名命中 > 按域名命中 > 最近使用。
- `save` 不需要解锁（只写不读），但空叶文档要记一条访问记录。
- `status` 方法：开关没开时 `status = "disabled"`，开了是 `"ok"`；两种情况都照常带上 `version`、`enabled`、`unlocked`、`unlockExpiresAt`。`status` 调用很频繁，不记访问记录，其余方法每次都记。
- 只有填了账号或密码的条目会出现在 `match` / `search` 里（只有验证码的动态密码不会）。
- 域名匹配：去掉协议、路径、端口和 `www.` 后比较主机名；网页域名**等于**条目网址的主机名，或是它的**子域名**才算命中（条目 `github.com` 命中 `gist.github.com`，反过来不算）。
- `reveal` 成功时记下这一条的最近使用时间，用于 `match` / `search` 排序。
- `save` 可另传 `name`；不传时用目标 App 的名称，拿不到用域名，再拿不到用包名。新建的条目类型是「密码」，`apps` 为传入的包名，网址为传入的域名。

### 1.5 解锁流程

1. 调用方 `reveal` 拿到 `status = "locked"` 和 `unlock`。
2. 调用方 `unlock.send()`，空叶文档弹出透明的 `VaultUnlockActivity`，用 `BiometricPrompt`（指纹，或锁屏密码兜底）验证。
   - Android 14 起，系统限制后台 App 借 `PendingIntent` 打开界面：调用方 `send()` 时要用 `ActivityOptions.setPendingIntentBackgroundActivityStartMode(...)` 允许后台启动，并把这个 `ActivityOptions` 的 Bundle 传给 `send(...)`，否则解锁界面可能不出现。
   - Android 8 没有 `BiometricPrompt`，直接用锁屏密码验证；手机没设锁屏时提示先去设置，然后关闭。
3. 验证成功后解锁 **5 分钟**，期间所有调用方的 `reveal` 都直接返回；**锁屏时立刻失效**。
4. 解锁界面关闭后，调用方回到原输入框：
   - 键盘：记住"待填充的 id + 包名 + fieldId"，下一次 `onStartInputView` 回到同一个框时自动重试 `reveal`，30 秒内有效。
   - 悬浮球：解锁界面关闭后，重新取当前窗口再填。

**测试**

## 3. 空叶键盘的任务

**识别输入框**（`KongyeIME.onStartInputView`）
- [ ] 密码框：`inputType` 的 variation 是 `TYPE_TEXT_VARIATION_PASSWORD`、`TYPE_TEXT_VARIATION_WEB_PASSWORD`、`TYPE_TEXT_VARIATION_VISIBLE_PASSWORD`，或 `TYPE_NUMBER_VARIATION_PASSWORD`
- [ ] 账号框：`TYPE_TEXT_VARIATION_EMAIL_ADDRESS` / `WEB_EMAIL_ADDRESS`，或 `hintText` 含「账号 / 帐号 / 手机 / 邮箱 / 用户名 / 登录名」
- [ ] 注册页：`hintText` 含「设置密码 / 新密码 / 确认密码 / 再次输入」

**登录填充**
- [ ] 识别到账号框或密码框时，调 `match(info.packageName)`，在候选栏显示「🔑 名称 · 打码账号」
- [ ] 点候选：`reveal` → 在账号框就填账号，再 `performEditorAction(IME_ACTION_NEXT)` 跳到密码框填密码；在密码框就只填密码
- [ ] 遇到 `locked` 按第 1.5 节处理
- [ ] 没匹配到时显示「🔍 搜索密码空间」，选中后调 `bind`，以后这个 App 直接推荐

**注册**
- [ ] 注册页的密码框显示「生成强密码」，调 `generate` 后上屏
- [ ] 2 分钟内同一个 App 里遇到「确认密码」框，推荐刚生成的那个
- [ ] 提交时询问是否保存，同意就 `save`

**记密码**
- [ ] 在密码框里由键盘上屏的字符只记在内存里（不含粘贴进去的内容）
- [ ] 按回车（`IME_ACTION_DONE` / `GO`）或离开这个框时，候选栏提示「存到空叶文档？」；点了就 `save`，不管存不存都立即清空内存

**隐私（务必逐条检查）**
- [ ] 密码框里的输入不进词库学习、不进联想、不进剪贴板历史、不写日志
- [ ] 设置里加总开关「密码填充」，关掉后完全不调 Provider
- [ ] 空叶文档没装或开关没开（`disabled`）时，候选栏不显示任何密码相关按钮

**已知限制（写进键盘说明）**
- 浏览器里键盘只知道是哪个浏览器，不知道是哪个网站，网页登录只能搜索
- 一加 / 小米等系统的"安全键盘"会在密码框替换掉第三方键盘，需在系统设置里关掉
- 银行类 App 用自己画的键盘，填不了

## 5. 建议顺序

1. 空叶文档：Provider + 解锁 + 开关
2. 空叶键盘：登录填充（做完这步就能用）
3. 空叶键盘：生成密码、记密码
4. 空叶悬浮球
5. （以后再说）空叶文档加系统自动填充服务（AutofillService），候选显示在键盘上，网页按域名自动匹配
