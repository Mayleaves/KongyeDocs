## 1. 目标

在手机上任何要填账号密码的地方：

1. **登录**：点到账号框或密码框时，输入框下面弹出候选（参考图：每行一个账号，下面是 `********`，最后一行「更多密码」），或者在空叶键盘的工具栏里出现「密码空间」。选一条，账号和密码一起填好。
2. **注册**：识别出注册页后，在密码框下面给出「生成强密码」，生成的密码**符合页面写的要求**（位数、必须包含哪几类字符、不能用哪些字符）。
3. **保存**：注册或改密码之后，把这一页填的信息（账号、手机号、邮箱、密码……）连同网址、网站或 App 名称存进空叶文档的密码空间。
4. **做不到上面的样子时**：至少能点「密码空间」→ 搜索 → 填入账号和密码。

密码只存在空叶文档里，键盘和悬浮球不保存任何密码。

## 2. 现状（v1，已完成）

| App | 已有 |
|---|---|
| 空叶文档 3.x | 密码空间（Keystore 加密）、对外接口 `VaultProvider`（`status` / `match` / `search` / `reveal` / `generate` / `save` / `bind`）、指纹解锁 5 分钟、访问记录、网址与适用的 App、浏览器包名不算适用的 App、更新时保留最近 3 个旧密码 |
| 空叶键盘 2.x | 识别账号框和密码框、候选栏显示匹配的账号、搜索、生成强密码、确认框复用、记住键盘输入的密码并提示保存 |
| 空叶悬浮球 3.x | 点了以后填充：找出密码框和账号框，浏览器读地址栏域名，`ACTION_SET_TEXT` 写入 |

v1 的问题：键盘只能把候选画在键盘区域里，看不到页面文字，在浏览器里也不知道网址；悬浮球只能点了以后用。所以做不到参考图那样的下拉框，也没法按页面要求生成密码、把整张表单存回去。

## 3. 总体方案：三条路线

| 路线 | 谁做 | 什么时候用 | 能做到什么 |
|---|---|---|---|
| **A. 系统自动填充（主力）** | 空叶文档新增自动填充服务（`AutofillService`） | 用户在系统设置里选了空叶文档作为自动填充服务，并且当前 App / 网页支持自动填充 | 参考图那样的下拉框，或者显示在空叶键盘工具栏里；拿得到网页域名、整页字段和文字；提交后系统弹出保存提示，交出所有字段 |
| **B. 键盘直连（退路）** | 空叶键盘 + v1 接口 | 路线 A 没有弹出时（App 关掉了自动填充、没选空叶文档） | 工具栏「密码空间」→ 列表 / 搜索 → 填入；注册时按提示文字生成；保存键盘输入的内容 |
| **C. 悬浮球（补位）** | 空叶悬浮球 + v1 接口 | 用户点悬浮球「填充密码」 | 贴着输入框弹出选择框；读整页文字识别注册页和密码要求；网页拿得到域名 |

**一个页面同一时间只出现一种候选**，规则见第 8 节。

## 5. 页面识别

三条路线都按本节规则识别。路线 A 和 C 能看到整页，路线 B 只看得到当前输入框（`EditorInfo` 的输入类型、提示文字、包名），所以只用得上带 ★ 的规则。

### 5.1 字段分类

按顺序判断，先命中的算数：

| 类型 | 判定信号 |
|---|---|
| 验证码 `otp` | Android 提示 `smsOTPCode`；网页 `autocomplete="one-time-code"`；★ 提示 / 标签 / id 匹配 `验证码\|校验码\|动态码\|动态密码\|短信码\|captcha\|otp\|verif(y\|ication)?\s*code` |
| 确认密码 `confirm` | ★ 是密码类型，且提示 / 标签匹配 `确认\|再次\|重复\|再输\|confirm\|repeat\|again\|re-?enter` |
| 新密码 `new` | Android 提示 `newPassword`；网页 `autocomplete="new-password"`；★ 是密码类型，且匹配 `新密码\|设置密码\|设定密码\|创建密码\|new\s*password\|create\s*password\|choose\s*a\s*password` |
| 当前密码 `current` | 网页 `autocomplete="current-password"`；★ 是密码类型，且匹配 `原密码\|旧密码\|当前密码\|current\s*password\|old\s*password` |
| 密码 `password` | Android 提示 `password`；网页 `type="password"`；★ `inputType` 为 4 种密码类型之一 |
| 手机号 `phone` | Android 提示 `phone`；网页 `type="tel"`、`autocomplete="tel"`；★ `TYPE_CLASS_PHONE`，或匹配 `手机\|电话\|mobile\|phone\|tel` |
| 邮箱 `email` | Android 提示 `emailAddress`；网页 `type="email"`；★ 邮箱输入类型，或匹配 `邮箱\|e-?mail\|mail` |
| 账号 `username` | Android 提示 `username`；网页 `autocomplete="username"`；★ 匹配 `账号\|帐号\|账户\|用户名\|登录名\|会员名\|user(name)?\|account\|login\s*id` |
| 其他 | 以上都不是 |

补充规则：

- 密码类型的框**一律开启隐私保护**（不学词、不进剪贴板、不能截屏），哪怕它被归为验证码。
- 页面上没有明确的账号框时，紧挨在第一个密码框前面的可编辑框当作账号框（类型取手机号 / 邮箱 / 账号里能判定的那个）。

### 5.2 页面类型：打分，不只靠一个正则

参考图本身就是反例：它是登录页，但页面上写着"未注册手机号验证通过后将自动注册"。所以页面文字只算弱信号，以字段信号为主。

| 信号 | 分 |
|---|---|
| 有 `new` 类型的字段 | +3 |
| 有 `confirm` 类型的字段 | +3 |
| 页面上有 2 个及以上密码框 | +2 |
| ★ 当前框提示匹配 `设置\|新\|确认\|再次` + 密码 | +2 |
| 提交按钮文字匹配 `^(立即)?注册$\|创建(账号\|帐号\|账户)\|完成注册\|sign\s*up\|register\|create\s+(an\s+)?account` | +2 |
| 标题文字匹配 `注册\|创建(账号\|帐号\|账户)\|新用户\|sign\s*up\|register\|join` | +1 |
| 只有 1 个密码框，且页面有 `忘记密码\|找回密码\|forgot\s*password` | −2 |
| 提交按钮文字匹配 `^登\s*录$\|^log\s*in$\|^sign\s*in$` | −2 |

判定：

- **改密码页**：有 `current` 字段，并且有 `new` 或 `confirm` 字段；或者标题匹配 `修改密码\|更改密码\|重置密码\|change\s*password\|reset\s*password`。
- **注册页**：不是改密码页，且总分 ≥ 3。
- **登录页**：其余有密码框的页面。
- **只有账号、没有密码框的页面**（分步登录的第一步）：当作登录页，只提供账号候选。

## 6. 解析密码要求

### 6.1 读哪里

1. 网页输入框的属性：`minlength`、`maxlength`、`pattern`、`passwordrules`（格式如 `minlength: 8; maxlength: 20; required: lower; required: upper; required: digit; allowed: [-_!@]; max-consecutive: 2`）
2. 密码框的提示文字（`hint` / `placeholder`）
3. 密码框附近的文字：同一容器里，以及紧挨在密码框下面的文字节点（最多取 3 个，每个不超过 200 字）
4. 提交失败后出现在密码框附近的报错文字。悬浮球再点一次时重新解析

页面上其他地方的文字不读，避免把无关内容当成密码要求。

### 6.2 正则

先把中文数字转成阿拉伯数字（`六→6`、`十二→12`、`二十→20`、`两→2`），再匹配：

```
长度范围  (\d{1,2})\s*(?:-|~|～|－|—|至|到|to)\s*(\d{1,2})\s*(?:位|个?字符|characters?)
最短      (?:至少|不少于|最少|不低于|不小于|at\s+least|minimum(?:\s+of)?)\s*(\d{1,2})\s*(?:位|个?字符|characters?)
最长      (?:不超过|最多|最长|不多于|不大于|at\s+most|maximum(?:\s+of)?|no\s+more\s+than)\s*(\d{1,2})\s*(?:位|个?字符|characters?)
必须包含  (?:包含|含有|须有|必须有|需要|须|must\s+(?:contain|include))[^，。；,.;]*?(大写|小写|字母|数字|特殊字符|特殊符号|符号|标点|uppercase|lowercase|letters?|numbers?|digits?|special\s+characters?|symbols?)
几种组合  (?:至少|任意)?(?:包含)?\s*(2|3|4)\s*种  /  (字母|数字|符号)(?:和|与|、|及|\+)(字母|数字|符号)(?:组合|混合)?
只能用    (?:仅|只)(?:能|支持|允许|可)?(?:由|包含|使用|输入)?\s*(字母|数字)(?:和|与|、|及)?(字母|数字)?
禁止      不(?:能|可|得|允许|支持)(?:包含|使用|含有?|输入)?\s*(空格|特殊字符|符号|中文|汉字|用户名|账号|手机号|生日|连续|重复)
允许符号  (?:特殊字符|符号)(?:包括|为|仅限|支持)[：:\s]*([!-/:-@\[-`{-~]{1,32})
```

### 6.3 解析结果

统一成一组参数（也就是第 7.2 节 `generate` 的参数）：

| 参数 | 含义 | 取不到时 |
|---|---|---|
| `minLength` / `maxLength` | 位数范围 | 8 / 64 |
| `require` | 必须有的字符类：`lower` / `upper` / `digit` / `symbol`（"字母"= `lower`） | `lower`、`digit` |
| `minClasses` | 至少几类 | 不限 |
| `symbols` | 允许的符号 | `!@#$%^&*_-+=?` |
| `noSymbols` | 不许用符号（写了"仅字母和数字"、"不能包含特殊字符"） | `false` |
| `forbidSequence` | 不许连续或重复（如 `abc`、`123`、`aaa`） | `false` |
| `avoid` | 不许包含的内容（同页已填的账号、手机号） | 空 |
| `pattern` | 网页输入框的 `pattern` | 空 |

能解析出来时，在候选上把要求写出来，比如「生成强密码 · 16 位 · 字母+数字」，让用户看得到是按什么生成的。

## 7. 接口变更（v1.1，向下兼容）

### 7.1 版本号

`status` 返回的 `version` **保持 1**：现有键盘和悬浮球只认 1，改成 2 它们会停用。新能力用新字段 `features` 声明：

| `features` 里的值 | 含义 |
|---|---|
| `generate.rules` | `generate` 支持第 6.3 节的参数 |
| `save.fields` | `save` 支持多个字段、页面类型、改密码 |
| `match.cert` | 匹配时核对 App 签名 |
| `autofill` | 空叶文档当前是系统选中的自动填充服务（空叶文档用 `AutofillManager.hasEnabledAutofillServices()` 判断自己是不是） |

调用方在用新参数之前先检查 `features`；没有就按 v1 的方式调用。

### 7.2 `generate`

传入（全部可选）：第 6.3 节的参数，`require` / `avoid` 是 `ArrayList<String>`。

返回：`password`；`summary`（给界面显示，如 `16 位 · 字母+数字`）；`satisfied`（Boolean，`false` 表示要求互相矛盾，只能尽量满足）。

生成规则：

- 长度取 `clamp(16, minLength, maxLength)`
- `require` 里的每一类至少 1 个；`minClasses` 不够时按小写、大写、数字、符号的顺序补
- `noSymbols` 时不用符号；有 `symbols` 时只用这些符号
- `forbidSequence` 时不出现 3 个连续字符，也不出现 3 个相同字符
- 不包含 `avoid` 里任何一项中长度 ≥ 3 的片段
- 有 `pattern` 时必须整串匹配；最多重试 50 次，还不行就返回 `satisfied=false`
- 只用 `SecureRandom`

### 7.3 `save`

v1 的参数照旧，新增：

| 参数 | 类型 | 说明 |
|---|---|---|
| `kind` | String | `register` / `login` / `change`，默认 `login` |
| `fields` | `ArrayList<Bundle>` | 每项 `type`（`username` / `phone` / `email` / `other`）、`label`、`value`、`secret`（Boolean） |
| `currentPassword` | String? | 改密码页的旧密码，用来找到原来那一条 |
| `rules` | String? | 第 6.3 节解析结果，写成 `passwordrules` 格式，存进条目，以后改密码时直接用 |

空叶文档的处理：

- **`account` 取哪个值**：调用方没传 `account` 时，按 `username` → `phone` → `email` 的顺序取第一个。其余字段存成条目的自定义字段，标签统一叫「用户名」「手机号」「邮箱」。
- **找已有条目**：
  - 普通 App：账号相同 + 包名在适用的 App 里
  - 网页：账号相同 + 主机名完全相同
  - `kind=change` 且没给账号：同一个 App 或网站下，当前密码等于 `currentPassword` 的那一条
  - 一条都找不到就新建
- **更新**：沿用 v1，最近 3 个旧密码存在隐藏字段里。
- **返回**：`id`、`result`（`created` / `updated`）、`fields`（存了几个字段）。

### 7.4 App 签名核对（`match.cert`）

- 空叶文档关联 App 时（`bind`、`save`、自动填充选中），记下这个 App 的签名证书 SHA-256：`VaultEntry.appCerts: Map<包名, 证书>`。
- `match` 只返回签名一致的条目。签名不一致的条目改为 `matchedBy = "cert_mismatch"`，调用方不能把它放进推荐，只能在搜索里显示，并且要提示用户。
- 读取其他 App 的签名需要能看到那个 App：空叶文档申请 `QUERY_ALL_PACKAGES`。这个应用不上架商店，没问题。

### 7.5 数据模型

`VaultEntry` 新增：

- `appCerts: Map<String, String> = emptyMap()`
- `passwordRules: String = ""`

自定义字段的标签固定为「用户名」「手机号」「邮箱」，方便以后识别。加密备份要带上新字段；旧数据读出来时这两项为空。

## 8. 去重与优先级

1. 空叶文档在 `status` 里报告 `autofill`。
2. **键盘**：
   - `autofill = true` 时，焦点进入账号框或密码框后先等 300 毫秒，看有没有收到系统推送的候选。
   - 收到了（走路线 A）：显示系统候选，**隐藏键盘自己的 v1 匹配列表**，只保留「密码空间」入口（用于搜索）；这个页面也**不再弹键盘自己的保存提示**，由系统来提示。
   - 没收到：走路线 B，照 v1 的做法。
3. **悬浮球**：只在点击时出现，点了就是用户明确要用它，不用和其他路线去重。
4. **保存提示**：一次提交只提示一次。键盘和悬浮球保存前，先在本机记下「包名 / 域名 + 账号 + 时间」，60 秒内同样的内容不再提示。

## 10. 隐私与安全（三个 App 都要遵守）

- 密码明文只在填入的那一刻经过键盘或悬浮球的内存，用完立即清除；不写日志、不进剪贴板、不进词库、不落盘、不进崩溃报告。
- 下拉框和候选在解锁前只显示账号（默认打码）和 `********`，不显示密码长度。
- 解锁规则不变：5 分钟有效，锁屏立刻失效。
- 不联网获取网站图标或名称。
- 访问记录照旧：记调用方、方法、包名或域名、条目名称、结果；不记账号和密码。
- 自动填充服务只读取有密码框或账号框的页面；分析完马上丢掉页面结构，不保存。

## 11. 已知限制

- 系统只能选一个自动填充服务。改成空叶文档后，手机自带的密码保险箱就不会再弹了。
- Chrome 要在它自己的设置里打开"使用其他服务自动填充"。其他浏览器能不能用，取决于是否支持自动填充，或者兼容模式能否生效。
- 有的 App 会关掉自动填充（微信、QQ、银行类较常见），这时只能用路线 B 或 C。
- 银行类 App 自己画的键盘，三条路线都填不了。
- 一加 / 小米等系统的"安全键盘"会在密码框里替换掉空叶键盘。路线 A 不受影响，路线 B 需要先关掉安全键盘。
- 悬浮球读不到用户自己输入的密码（屏幕上显示为圆点）。

1. **空叶文档 v1.1 接口**：`features`、带要求的 `generate`、多字段 `save`、签名核对。做完键盘和悬浮球就能开始接
2. **空叶文档自动填充服务：登录**（S1、S3、S5、S13）

和本文前面写法不同的地方：

- **`generate` 多收三个参数**：`ruleText`（调用方读到的提示 / 附近文字，空叶文档统一解析，三个 App 不用各写一套解析）、`passwordrules`（网页属性原文）、`allowed`（只能用哪几类字符，如数字密码框传 `["digit"]`）。v1 的 `length` 仍然是固定长度。
- **`reveal` 多一个返回状态 `cert_mismatch`**：条目记过这个 App 的证书、但现在不一样时返回；调用方提醒用户后带 `confirmCert=true` 再调。
- **`match` 只有声明了 `features: ["match.cert"]` 的调用方才会收到 `cert_mismatch` 条目**，v1 的键盘和悬浮球看不到它们，不会误推荐。
- **签名是"第一次信任"**：3.2 及以前关联的条目没有记证书，照常推荐；下一次通过键盘、悬浮球或自动填充用它时补记。
- **键盘保存时机**：新密码框输完不提示，到确认框输完（两次一致）或提交时提示一次；键盘收起时先记着，不提示。
- **悬浮球「保存这一页」只能存它自己生成并填入的密码**：用户自己输入的密码在屏幕上是圆点，读不到，会提示改用空叶键盘保存。
- **自动填充界面禁止截屏**：真机截图是黑的，界面内容由无障碍文字核对。

还没有在真机上走通的（需要你在手机上操作）：把空叶文档设为系统自动填充服务后，在真实 App / Chrome 里弹下拉框、键盘工具栏候选、提交后保存；悬浮球 3.1.0 在索尼上的贴边选择框（索尼上的悬浮球还是旧签名，装新版要先卸载）。
